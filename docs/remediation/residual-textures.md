# Residual texture remediation

## GregTech rendering-error sentinel

The installed GregTech 5.09.54.265 `Textures.GlobalIcons.RENDERING_ERROR`
returns the Minecraft block atlas missing sprite through `getMissingNo()`.
It is not a required PNG named `RENDERING_ERROR.png`. Point its Web Map
texture record at a bundled, deterministic 16x16 black/magenta checkerboard,
generated by `tools/generate_missing_texture.py`, preserving its texture ID
and consumers. This implements the error sentinel's real appearance and does
not mark a missing required texture optional.

Validation: decoded PNG signature, 16x16 RGBA dimensions, four 8x8 quadrants,
CRC and deterministic regeneration. Live pixels remain subject to fixture
render validation.

## Process only fallback images

Texture records may now declare `processoronlyfallback=true`. Resolution
metadata from the existing loader is copied to each pack's decoded image after
loading; no filename guessing or shared mutable mapping flag is used. A
premade original image follows the ordinary GRID path unchanged. Only an
actual fallback image runs the custom processor. The source grid and processor
output counts must agree, so either route produces the same texture indices.
This supports procedurally derived mod textures while honoring original
resource-pack images. Required/optional errors retain their existing handling.

Validation: reviewed original/fallback lookup identity and per-pack storage;
`git diff --check` passes. The ExtraUtilities processor regression exercises
the intended original/fallback behavior alongside the actual mod's algorithm.

Exact sentinel pixel validation additionally uses Minecraft 1.7.10's
`TextureUtil` static initializer: color -524040 (RGBA 248,0,248,255) appears
in the top-left/bottom-right 8x8 quadrants, and -16777216 is black in the
other two. Every decoded pixel and every PNG chunk CRC was checked against
that source pattern, rather than assuming generic full-intensity magenta.

## ExtraUtilities compressed blocks

Sixteen absent compressed PNG names are generated by ExtraUtilities 1.2.12's
`TextureComprBlock`, not shipped files. Each record now tries the original
compressed image first (preserving pre-generated resource-pack images) and
falls back to its actual vanilla cobblestone/dirt/gravel/sand source. Only the
fallback is transformed by `ExtraUtilitiesCompressedTextureProcessor`, at the
correct compression level. Existing support IDs and block metadata remain.

The effect was derived from the installed JAR's bytecode, including its
unusual negation of packed RGB, border/vignette and level-dependent contrast.
It does not substitute a plain vanilla texture for a compressed block.
Web Map takes the first square animation frame, as a deterministic static map.

Validation: `EXTRAUTILITIES_JAR=/path/to/extrautilities-1.2.12.jar python3 -m
unittest discover -s tools/tests -p test_extrautilities_compressed.py` executes
the actual installed `TextureComprBlock` against small Minecraft boundary
doubles and compares every generated pixel with the new processor, for all
eight compression levels and 8/16/32-pixel source resolutions. Premade image
pixels are checked against the mod's original-resource early-return behavior.
The JAR is not committed. The 16 declaration fallback paths, levels and
processor flags are checked separately against their corresponding materials.

## Native-resolution model atlases

`AtlasMesh.split(double[15], columns, rows)` clips each xyz/UV triangle into
ordinary 16-pixel atlas cells. Returned `Triangle.vertices` contains xyz/UV
coordinates for three vertices, with local bottom-origin UVs, and
`Triangle.texture` is the top-origin row-major GRID index. Coordinates and
winding are interpolated without changing surface area. Repeating/mirrored
UVs are supported; finite-coordinate and UV-span checks reject invalid data.
This lets OBJ and baked cuboid models retain atlas detail through the existing
GRID texture pipeline instead of downsampling an entire atlas to one block tile.

Validation: `python3 tools/test-atlas-mesh.py` compiles and executes the real
helper, checking400 randomized triangles over five atlas resolutions, total
surface area, bounds, row orientation, repeat wrapping, constant UV edge cases
and rejection of non-finite coordinates.

## Source-baked static ModelRenderer models

`tools/bake-techne-model.py` imports literal independent cuboids from a mod's
ModelRenderer constructor, including box UV offsets, pivots, local Euler
rotations, mirroring at construction time, inflation and the declared atlas.
It applies the renderer's explicit outer transform supplied on the command
line, rejecting child hierarchies, nonliteral coordinates and multiple-box
constructs until explicitly supported. `BakedMeshRenderer` loads the resulting
CPU-only geometry and uses `AtlasMesh` to preserve atlas cell resolution.
There is no linkage to a mod's client model class or GL methods on the server.

Validation: `tools/test-techne-baker.py` checks supported/rejected source forms
and the block-space TESR transform. With `--minecraft-jar` and
`--runtime-classpath`, it executes the actual Minecraft 1.7.10 `ModelBox` class
(without rendering) and compares every exported position and UV for ordinary
and mirrored cuboids. `tools/test-baked-models.py` exercises the real patch
factory, atlas index/UV bounds and exported model bounds.

## Source-defined part orientation

Baked parts can select rotations from bounded saved-state tables around their
source pivot. The renderer requests only the declared NBT fields and caches
immutable meshes by the selected finite poses. Unknown values share a default
pose rather than creating an unbounded cache. The baker explicitly imports
Blood Magic's input/output direction switches and maps model-space axes
through the TESR outer transform; static frame pieces remain unchanged.

Validation: source-baked group centroids point in each of the six expected
Forge directions. Actual renderer tests exercise all36 input/output pairs and
cache identity, with unchanged patch coverage and native atlas coordinates.
Static life-infuser and node models are rechecked as regression controls.

## Blood Magic mimic block

The mimic block has no fixed image: `TEMimicBlock` saves its slot0 ItemBlock in
`Inventory`, and `MimicBlock.getIcon` reads that block's metadata-specific face
icons. `InventoryMimicRenderer` now selects that saved item, resolves numeric
or named Minecraft item IDs to their underlying block, and copies its six
face textures and static tint. Empty/non-block/invalid entries keep the source's
missing-sprite appearance, supplied by the explicit bundled checkerboard.
There is no substitution of an arbitrary solid block for a dynamic mimic.

Validation: the real texture-map and patch factory tests cover slot0 selection,
metadata7, distinct directional faces, copied tint, non-block entries, absent
inventory and out-of-range metadata. Standard block metadata0..15 is supported;
item-only variants beyond the block metadata range remain an explicit limitation.
