# Processor tile allocation and resource reachability

The isolated installed-pack fixture on candidate 7b797c4 loaded 34 missing legacy ultra-dense AE2 cable images even though the AE2 loader correctly rejected their unregistered item metadata. There was no `AE2 part registry unavailable` warning. The installed `appliedenergistics2-rv3-beta-1095-GTNH.jar` (SHA256 `f66e1d5db3496a209f48e6264c566264c50b0f00f071e2a29efc93611696dbea`) has no UltraDense resources or PartType entries. `javap -c -p` confirms `ItemMultiPart.getTypeByStack` returns `InvalidType` when the metadata is absent from `registered`. Source in AE2 rv3-beta-1095 confirms ordinary cable ranges 0/20/40/60/520; legacy ranges 540 and 560 are absent.

The texture parser preallocated every custom processor output using `parseTextureIndex`, which marks its source file used. This happened while reading texture declarations, before the AE2 registry check in the later moddata record. The fix keeps the contiguous preallocation and texture-name registration, but restores the declaration's previous used flag afterward. Actual block and moddata texture references still mark the resource used. Existing active references remain active if a processor reserves outputs again. No missing resource is marked optional or hidden when an active reference exists.

`python3 tools/tests/test_ae2_cable_registry.py` compiles the production allocation, parsing and tile methods together with the production AE2 loader. It exercises contiguous/stable output IDs, inactive unregistered cable resources, activation of registered legacy cable images, preserving an already active declaration, modifiers, absent registries, linkage errors, and required texture failures. Both tests pass. The next isolated full-pack fixture cycle must confirm the 34 paths move to inactive declarations.
